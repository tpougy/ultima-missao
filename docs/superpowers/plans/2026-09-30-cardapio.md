# Votação do Cardápio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página de Cardápio (default) com votação por item, totalizador
compartilhado e Admin para configurar período, pagantes, sessões e itens,
integrada via navbar com a votação de data existente.

**Architecture:** Regras puras em `src/lib/menu.ts` (sem InstantDB, testadas
com `bun test`) transformam o resultado de uma única `useQuery` em cards →
sessões → itens com placar e totais. Ações de escrita ficam em
`src/lib/menuDb.ts`. Hash routing (`src/lib/router.svelte.ts`) + `NavBar`
integram tudo no `App.svelte`, mantendo os gates existentes.

**Tech Stack:** Svelte 5 (runes), TypeScript, Vite, Bun, InstantDB
(`@instantdb/svelte`), lucide-svelte, CSS puro com tokens de `app.css`.

**Spec:** `docs/superpowers/specs/2026-09-30-cardapio-design.md`

## Global Constraints

- Svelte 5 runes apenas; nada de `export let`, `$:` ou APIs legacy.
- Sem dependências novas.
- CSS puro reutilizando tokens `--color-*` de `src/app.css`; mobile-first, `max-width: 32rem`.
- Textos de UI em pt-BR.
- Perms abertas (`"true"`), igual às entidades existentes.
- Voto = link `menuItems.likedBy ↔ participants.likedMenuItems`; só conta se `menuVoter === true`.
- Item no cardápio ⇔ `voters > 0 && support * 2 >= voters`.
- Totais armazenados/calculados em valores totais; divisão por pagantes só na UI.
- Card Geral (sessões sem `date`): público só se tiver sessões; admin sempre.
- Senha do app e senha de admin continuam funcionando como hoje.

## Review Focus

1. Preço inválido no admin (vazio, `NaN`, negativo) → não grava, mantém valor anterior.
2. Período inválido (sem datas, saída < chegada, intervalo absurdo) → sem dias; limitar a 62 dias.
3. Pagantes vazio/0 → custo por pessoa exibe "—" sem `Infinity`/`NaN`.
4. Empate de `order` (criações concorrentes) → ordem estável por `id`; mover renumera a lista.
5. Participante removido no admin de data → links somem por cascade; placar e votantes recalculam (coberto por derivação; testado via "likes de não-votantes/ausentes ignorados").
